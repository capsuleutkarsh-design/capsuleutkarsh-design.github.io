The nodes

Everything a plate needs before comp

Each job is a node. Wire them together, render, and deliver. Everything runs on your machine: after setup the app never downloads anything and never uploads a frame.

Media

Media Plate

EXR, DPX, TIFF and PNG sequences or video. Keeps the original for delivery and makes a 16-bit display copy for the AI nodes; ACES, log and video colour spaces; optional half-size working copy for 4K.

Matte

Super Matte

Click, box or text prompts. SAM 1, SAM 2 (SAMURAI tracking) or SAM 3, refined into soft 16-bit mattes, one per layer.

SAMSAMURAISAM 3ViTMatteMEMatteVideoMaMaGroundingDINO
Matte

Matte to Shape

Mattes become Nuke roto shapes whose points stay on the object, with feather. Outline mode for any object; body-parts mode cuts a person into head, torso and limbs, and limbs behind the body fade out using the depth map.

MediaPipe Pose
Keying

Corridor Keyer

Green and blue screen keying with CorridorKey: straight or premultiplied linear EXR, despill, matte clean-up and anti-flicker.

CorridorKeyBiRefNetGVM
Depth

Depth

Depth Anything V2: stable relative depth (0–1 over the shot) or metric depth in metres, as float EXR.

Depth Anything V2
Colour

Grade · OCIO ColorSpace

A Nuke-style grade and OpenColorIO conversions in scene-linear, on the full-quality frames.

OpenColorIOACES
Tracking

3D Camera Tracker

COLMAP 4.2 solve (global or incremental) with SIFT, LightGlue, ALIKED or LoMa features, and shot presets. Given a matte, it ignores moving objects.

COLMAPLightGlueALIKEDLoMa
Output

Unified Output

Delivers everything: EXR layers (colour in ACEScg or another linear space, mattes in A, depth in Z), a camera for Nuke, Blender or USD, roto shapes, and a Nuke script with a Read per layer.

Colour

The ACES studio OpenColorIO config. The working space is ACEScg and the viewer uses the ACES SDR view. Highlights above 1.0 are kept.

Frame numbers

Every file keeps the plate's own frame numbers: 1001 stays 1001. The timeline's In/Out limits every render.

Rendering

Renders are cached per node and redone only when something upstream changes. Stop, Freeze and Bypass work as in Nuke.

Quick start

Your first matte

Three nodes take you from a plate to a matte in Nuke or Blender.

Media Plate→ Super Matte→ Unified Output→ Nuke / Blender
01Load the plateClick Load media… above the node list and pick one frame of a sequence (EXR, DPX, TIFF, PNG…) or a video. A Media Plate node appears. You can also drop the file onto the graph.
02Add a Super MatteClick Super Matte in the node list (under Matte) and wire the Media Plate's Video Plate output into its Video Plate input.
03Click the objectSelect the node and click in the viewer. A click adds a point, Shift+click leaves something out, Ctrl+click removes a point. One layer per object.
04ExecuteClick Execute at the bottom of the node's settings. It renders the matte for the whole shot, or the timeline's In/Out. Where the matte drifts, go to that frame and click again.
05Unified OutputAdd it (under Output). Wire Super Matte's Alpha Matte and the Media Plate's Video Plate into it, set Output Folder (blank uses the project's), and click Execute.
06Into Nuke or BlenderOpen the written _reads.nk in Nuke, or run the Blender import script for a camera. What gets written.
Straight into your comp

Getting results into Nuke and Blender

Unified Output writes everything into its output folder, and every file keeps the plate's frame numbers.

WhatWhereHow to use it
Plate, keyed RGBA, mattes, depth<layer>\<shot>_<layer>.<frame>.exrMattes are in the alpha channel, depth in Z.
A Read for every layer, plus the Roto nodeexports uke\<shot>_reads.nkOpen it in Nuke, or import it into your script. The Contour_Roto node is wired under the plate's Read.
Roto shapes (Matte to Shape)exports uke\<shot>_roto.nkOpen it in a text editor, copy everything, click in Nuke's node graph and press Ctrl+V. A Roto node builds the animated shapes.
Camera and point cloud (3D Camera Tracker)tracking\Nuke: open camera_track_nuke.nk (or load camera_track.chan into a Camera). Blender: open import_to_blender.py in the Scripting tab and click Run Script.
What was written<shot>_export.jsonColour spaces and frame ranges of every layer.

Colour in Nuke

Colour layers (plate, keyed RGBA) are written in ACEScg by default. In Nuke, set Project Settings › Color › OCIO config to an ACES config, then set each colour Read's Input Transform to ACEScg. Mattes and depth are data: their Reads are set to raw, so leave them. The _reads.nk carries a note with the same steps.

Alembic and .blend

Point Blender (for Alembic and .blend) on the Unified Output node at your blender.exe, and the camera is also written as tracking\camera_track.abc and tracking\camera_track.blend.

What it needs

Requirements and GPU memory

The AI nodes run on an NVIDIA graphics card through PyTorch 2.5.1 with CUDA 12.1.

Windows

Windows 10 or 11, 64-bit. Installs for your user only; no administrator rights needed.

NVIDIA GPU

Driver 531 or newer (CUDA 12.1); the newest Studio or Game Ready driver is best. Without an NVIDIA card the AI nodes cannot run at a usable speed.

Disk

About 40 GB free: about 6 GB for the app, 24 GB for the AI models, and room for renders.

RTX 50-series

Not supported on the GPU yet: this PyTorch has no code for Blackwell cards. The app tells you, then runs the AI nodes on the CPU, which is very slow. Support is planned for a later version.

Rough VRAM per node

NodeRough VRAM (HD plates)
Media Plate, Grade, OCIO ColorSpace, Matte to Shape, Unified Outputlittle or none
Depth≈ 2–4 GB Small to Large model; more with a bigger Detail setting
Super Matte: SAM 1, SAM 2 (SAMURAI) or SAM 3, with ViTMatte or MEMatte≈ 6–8 GB
Super Matte with the VideoMaMa refiner> 16 GB
Corridor Keyer≈ 10 GB at Processing Resolution 2048; much more at 4096
3D Camera Tracker (COLMAP)≈ 2–4 GB

In short: 8 GB is enough for most nodes on HD plates, 12 GB or more is comfortable, and VideoMaMa wants a 24 GB card. These are rough guides from the model sizes and the project's notes, not tests on every card; bigger plates and higher settings need more. The app's footer shows the card's VRAM use while you work.

Get it

Download and install

The installer holds the app and its Python environment. The AI models (about 24 GB) are not in it: some model licences do not allow sharing them, so they are downloaded from their official sources during setup.

  1. Download every file from the latest release: the setup .exe and the .bin file(s) next to it.
  2. Keep them in the same folder and run the .exe. It installs to %LOCALAPPDATA%\Programs\Contour VFX for your user only, with no admin rights.
  3. The installer is not code-signed yet. If Windows shows “Windows protected your PC”, click More info → Run anyway.
  4. Get the models. On the last page, leave Download AI models ticked. It resumes if interrupted and checks every file. Or do it later from Start menu › Contour VFX › Download AI models.
  5. Start Contour VFX from the Start menu and load a plate.

Latest release

Already have an earlier 2.x version with its models? Install over it: the models are kept.

ContourVFX_Setup_2.2.0-beta.exe
ContourVFX_Setup_2.2.0-beta-1.bin (and any further .bin)
Download them together. The installer cannot work without the .bin files beside it.

Offline model pack

For PCs without internet. On a PC that has the models, build\BUILD.bat models writes 2 GB ZIP parts (ContourVFX_Models_2.2.0-beta.zip.001, .002, …). Install them from the installer's Offline models page, AI models › Install from offline pack in the app, or option 3 of FIRST_SETUP.bat. Every file is checked against its SHA-256.

The pack is for your own computers only: please don't upload it, because some model licences forbid that.

Two models need a step from you

  • SAM 3 is gated: request access at facebook/sam3 on Hugging Face and sign in before downloading it.
  • MEMatte (a Super Matte edge refiner) is only shared on Google Drive: download it by hand, see MODEL_DOWNLOADS.md.

Everything else works without them.
